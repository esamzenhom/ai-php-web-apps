# Keep your recovery key safe

Backups are encrypted. Open **Admin → Settings → Backup recovery key**, confirm
your password (and authenticator code if enabled), and download your recovery key.
Keep it in a password manager or another safe place, separately from your backups.
Anyone with both can recover your saved account and API keys. If the computer is
lost and you have no separate key copy, the backups cannot be recovered.

The local key lives in `application/data/recovery/`; it is never part of backups,
public source packages or reset archives. Authenticator recovery codes are different:
they let you sign in when you lose your authenticator. Save those separately too.

## For your assistant

Run these commands from `application/`. Never show private key contents in chat.
New backups contain `.enc` payloads: website database, admin SQLite, API encryption
key, source snapshot and private website files. Backup creation verifies a complete
decrypt-and-hash round trip before success. It excludes CLI login credentials;
reconnect those through admin Settings after full recovery.

After the new recovery key is prepared, convert older backups with
`docker compose exec -T worker php bin/encrypt-backups.php`. Explain beforehand that
this replaces each plaintext file with verified ciphertext, preserves its content,
and requires the separate recovery key for future restores. The command stops on
failure and removes a plaintext file only after its encrypted copy verifies.
Historical symbolic links are saved as encrypted `.symlink.enc` target metadata;
they are never followed. Recovery produces `.symlink` text files: review targets
before recreating any links. Temporary CLI links can be regenerated by reconnecting. Keep
an independently saved recovery key before moving backups off the computer.

Website-only restore: `make restore FILE=backups/<folder>/database.dump.enc`.
This warns and creates a fresh backup before replacing website records.

For a lost computer, stage the downloaded recovery JSON at
`data/control/recovery-import.json` in a fresh checkout **before its first Start**.
Run `python3 bin/init-app.py` to create this checkout's local configuration, then
`docker compose build prepare` and
`docker compose run --rm --no-deps prepare php bin/recovery.php import`.
Import refuses to replace a different existing key. Run Start afterward to prepare
ownership and services. Move encrypted backups into this checkout's `backups/`.

To recover one file without overwriting live records:
`docker compose run --rm --no-deps prepare php bin/recovery.php decrypt backups/<folder>/<file>.enc`.
The verified result goes into private `data/control/recovered/`; existing results
are never overwritten. Run preparation afterward to restore private ownership.

To recover a whole backup folder while preserving nested paths, use
`docker compose run --rm --no-deps prepare php bin/recovery.php decrypt-folder backups/<folder>`.
After either decrypt command, run `docker compose run --rm --no-deps prepare` to
restore the local owner’s file permissions. Every file must authenticate before the completed folder appears in
`data/control/recovered/<folder>`. This also supports old reset folders after
legacy conversion. A failed recovery removes its incomplete staging folder.

For full recovery, first explain the exact overwrite and obtain the owner's
confirmation; back up current state, stop the app, then recover matching
`admin.sqlite.enc` and `key.enc` together. Restore website source from `files.json.enc`,
private website files from `site-data.tar.enc`, and the website database. Preserve
current files until successful sign-in and record checks. Reset archives additionally
contain encrypted `data.tar.enc` and `environment.enc`; their recovery key is outside
the archive. Restore into a separate checkout for inspection whenever possible.

Temporary decrypted files are private but readable by the computer's administrator.
Remove recovery working files after successful verification. Encryption protects
copied backups; it does not protect against compromise of the running host/admin.
